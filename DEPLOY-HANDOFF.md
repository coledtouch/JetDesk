# JetDesk Production Deployment Handoff

## Current status

This package is the deployed production source of truth as of September 1, 2026, app version `v7baf7151`, live at https://www.jetdesk.ai. It contains the Codex production-polish pass (originally `v2236becd`) plus the fixes and additions recorded below. No secret values are included; `site/wrangler.toml` carries placeholders.

- Deployment project: `meridian-flight-desk` (Cloudflare Pages)
- App and deployment directory: `site`
- Build: run `python3 assemble_pwa.py` from `site`, then deploy `dist` with Wrangler from `site` so `functions/` is included
- See `site/README.md` for local dev, cache rules and deploy commands

## What is configured in production

- Cloudflare Pages with D1 (`DB`), KV (`PRICES`), var `REQUIRE_VERIFY=1`, and secrets: `AUTH_PEPPER`, `ADMIN_EMAILS`, `EIA_API_KEY`, `OILPRICE_API_KEY`, `STRIPE_SECRET_KEY`, `STRIPE_PRICE_MONTHLY`, `STRIPE_PRICE_ANNUAL`, `STRIPE_WEBHOOK_SECRET`, `EMAIL_API_TOKEN`. Optional, not yet set: `NOTAM_API_BASE` plus `NOTAM_CLIENT_ID`/`NOTAM_CLIENT_SECRET` (or `NOTAM_API_KEY`) for the NOTAM card
- Scheduled Worker `jetdesk-cron` (`site/workers/cron`, daily 13:00 UTC): trial ending and trial ended emails, prunes expired sessions, rate limit rows and events older than 400 days. Secrets `EMAIL_API_TOKEN` and `CRON_KEY`; manual run at `https://jetdesk-cron.<subdomain>.workers.dev/run?key=<CRON_KEY>`
- Data refresh: `site/refresh_data.py` downloads the current FAA NASR 28 day cycle and OurAirports and rebuilds `airports_us.json`; `site/.github/workflows/refresh-data.yml` runs it weekly and deploys when the repo is pushed to GitHub with `CLOUDFLARE_API_TOKEN` and `CLOUDFLARE_ACCOUNT_ID` secrets (not yet wired, no repo)
- Stripe live: product "JetDesk Pro", $9.99/mo and $79/yr prices, webhook to /api/billing/webhook, Managed Payments on (product tax code txcd_10103001), full checkout branding (icon, #070B14 / #0E7CFF, statement descriptor JETDESK.AI), support email and privacy/terms URLs set
- Outbound email: Cloudflare Email Service REST API from hello@jetdesk.ai via `EMAIL_API_TOKEN` (Email Sending: Edit). Inbound hello@ routes to the owner's Gmail
- Legal pages at /terms/ and /privacy/, generated by the build from `site/legal.py`, linked from the app and registered with Stripe

## Deployment record

### Round 1 (Codex v2236becd, deployed as v8f7a6ebd)

Rebuilt on Linux (LF endings account for the version hash difference) and deployed after review, with three fixes:

1. `app_head.html`: `.hero .phone` sets `color: var(--ink)` so the phone mock's numbers are visible in light mode.
2. `assemble_pwa.py`, `pwa.js`: icons referenced by content-hashed filenames; `/favicon.ico` cached a day instead of a year. The custom domain's edge cache had kept old icons under plain immutable names.
3. `lib/util.js`, `schema.sql`: `rateLimit()` counts in the D1 `rate_limits` table (created additively on production). KV reads are edge-cached for 60 s, so the previous KV counter never triggered inside a burst; login and verification limits now actually return 429.

Full production smoke test passed: redirects, security headers and CSP, landing at 320/390/1440 both themes with no horizontal scroll, PWA precache and offline reload, register / verify / sign out / sign in / delete, airport search and detail, wx / winds / market APIs, Stripe endpoints clean 503 before keys, then live checkout verified after keys.

### Round 3 (v5476ef2b, v1a00c02c, v7baf7151, current)

Three deploys, each smoke tested on production. Schema changes are additive and were applied to the production D1 by hand (`site/migrations.sql` lists them; `schema.sql` is the full current shape).

Account and security
1. Password reset: `/api/auth/forgot` (always returns ok, rate limited) and `/api/auth/reset` (code, new password, revokes every other session). Two step modal in the sign in sheet.
2. Verification enforced when `REQUIRE_VERIFY=1`: `/api/data` writes, invites and checkout return 403 `code: "verify"`; the client opens the verify modal on that code. Set in `wrangler.toml` and live.
3. Security card in Account: change password, change email with a code sent to the new address (`/api/auth/email`), device list with revoke others (`/api/auth/sessions`).
4. Owner role: invites take `role: member | viewer`; viewers see everything but every write returns 403 `code: "viewer"` and the UI hides edit controls (`canEdit()`).

Lifecycle and email
5. `lib/email.js` rebuilt on the brand kit: Midnight header with the mark (`/mark-email.png`), Ion rule, white card, legal footer; templates for verify, welcome, reset, email change, trial ending, trial ended, test.
6. `lib/lifecycle.js`: `touch()` records `last_seen` and a daily active event; `trialNotices()` sends trial ending (2 days) and trial ended once each (`users.notices` JSON). Runs lazily on `/api/me` and daily from the cron Worker.
7. `lib/metrics.js` and `events` table; `/api/admin/stats` (admin only) returns 30 day signups, logins, verifications, checkouts, subscriptions, actives, plus account counts. Metrics button on the admin card.

Pilot features

10. Route fuel stop finder (Pro): every Jet A field within a corridor of the route ranked by net savings, with "Use in calculator".
11. Owner trip brief (Pro): `POST /api/brief` stores a snapshot in KV for 180 days; `/brief/<id>` is a server rendered, print ready, noindex page.
12. NOTAM card wired behind `/api/notams`; shows nothing until `NOTAM_API_BASE` and credentials are set (FAA NMS access is requested by emailing notams@faa.gov). Flags runway closures.

2. Landing page hero, logo, images, pricing, CTAs, FAQ accordions, light and dark themes at 320, 390 and 1440 px with no horizontal overflow.
3. /robots.txt, /sitemap.xml, favicon, Open Graph image, title, description, canonical, structured data, /terms/, /privacy/.
4. Registration, sign in, verification delivery and wrong-code and resend limits (429 after 10 wrong codes), forgot and reset password, change email, sessions list, sign out, account deletion.
4a. Unverified account gets 403 `verify` on a data write; viewer gets 403 `viewer`.
5. Airport search and details, weather, winds, route and fuel calculations with real API responses.
6. Owner brief page renders and prints; /notes/ pages; /api/notams returns configured:false or live data.
7. Stripe monthly and annual checkout, webhook fulfillment on a real payment, subscription state, customer portal.
8. PWA installation and a repeat visit offline.
9. Browser console and Cloudflare logs clean.

## Guardrails

- Never place secret values into source files or this document.
- Do not initialize or migrate the production D1 blindly; every statement in `schema.sql` is additive (`IF NOT EXISTS`), check state first.
- The cron Worker needs its own Workers scoped token; a Pages only or Email Sending only token cannot deploy it.
- Confirm real bindings in the private Cloudflare configuration before deploying from a fresh checkout.
