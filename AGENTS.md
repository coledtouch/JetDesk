# AGENTS.md

Instructions for a coding agent (Codex or similar) working in this kit. Read `BRAND.md` first, then this file. The job here is design, image, logo and hero work for JetDesk.AI, plus wiring those assets into the site sources so the owner can rebuild and deploy.

## What this kit is

`site/` is a sanitized snapshot of the production JetDesk.AI codebase (Cloudflare Pages, plain HTML + a single vanilla JS bundle, Pages Functions backend). It is complete enough to build and run locally. It contains no secrets: `wrangler.toml` carries placeholders and there is no `.dev.vars`. Do not invent values for the placeholders; the owner fills them in his own checkout.

```
jetdesk-brand-kit/
  BRAND.md                 brand rules: mark, palette, type, voice, imagery
  AGENTS.md                this file
  README.md                human overview and quick start
  brand/tokens.css         production CSS custom properties (light + dark)
  brand/tokens.json        the same tokens as data, plus logo geometry
  logo/                    mark.svg, mark-tile-dark.svg, lockup-dark.svg, lockup-light.svg, PNG icons
  design/                  the design canvas sources (.dc.html artboards + canvas.json)
  screenshots/             production captures of the landing page and app tabs
  prompts/image-prompts.md ready-to-run prompts for hero, logo variants, OG image, store screenshots
  site/                    the app sources (see below)
```

`site/` layout:

```
site/
  app_head.html      <head>, all CSS, header markup, tab bar, empty <main> containers, modal and sheet shells
  app.js             the whole client: dataset lookup, calculators, tabs, landing page (renderWelcome), auth, sync
  pwa.js             service-worker registration, install banner, footer version
  assemble_pwa.py    build: inlines fonts.css, writes dist/index.html, manifest, sw.js, _headers
  assemble.py        legacy single-file build (artifact preview); not needed for the site
  build_dataset.py   rebuilds airports_us.json from OurAirports + FAA NASR (needs network)
  airports_us.json   4,493 US paved-runway airports, embedded into the bundle at build time
  icon.html          renders the app icon at 512 px (Playwright screenshot; ?pad=0.1 for maskable)
  schema.sql         D1 schema (users, sessions, ops, op_members)
  wrangler.toml      Pages config with <PLACEHOLDER> ids
  functions/         Pages Functions: _middleware.js (canonical host 301) and api/* endpoints
  lib/               shared backend code: auth, crypto, data ops, email, stripe, util
  dist/              build output folder. Only static assets are checked in: fonts/, icons/, manifest, _headers.
                     dist/index.html and dist/sw.js are generated by assemble_pwa.py and are not in the kit.
```

## Build and run

Requirements: Python 3.10+, Node 18+ (for wrangler), Playwright with Chromium only if you regenerate icons.

```bash
cd site
python3 assemble_pwa.py            # writes dist/index.html, dist/sw.js, dist/manifest.webmanifest, dist/_headers
npx --yes wrangler@4 pages dev --port 8794   # serves dist/ with Pages Functions at http://localhost:8794
```

Without Cloudflare bindings the frontend still renders fully in browse mode (landing page, airports, runway verdicts, calculators with local state). Auth, sync, weather, winds and market endpoints need the KV, D1 and secrets the owner has in production; do not try to stub them into the sources.

For local backend work the owner uses a `.dev.vars` with `AUTH_PEPPER`, `ADMIN_EMAILS`, `STRIPE_*` and a local D1 created with `npx wrangler@4 d1 execute jetdesk --local --file schema.sql`. None of that is needed for design work.

The service worker caches aggressively. When checking visual changes in a browser, use an incognito window or turn on "Update on reload" in DevTools > Application > Service Workers. There is no query-string switch to disable it.

## Where things live in the code

- Brand tokens: top of `app_head.html` (`:root`, the `prefers-color-scheme` block and `:root[data-theme="dark"]`). `brand/tokens.css` is the same content; if you change one, change both.
- Header and mark: `app_head.html` around the `<header>`; the inline SVG uses `var(--card)`, `var(--line2)` and `var(--acc)` so it follows the theme. Keep it inline (no external SVG requests).
- Landing page: `renderWelcome()` in `app.js` (search for `/* ================= WELCOME`). It builds the hero, the phone mock, the "Built on official data" strip, savings stats, six capability demos, how it works, pricing, FAQ and the final CTA as one HTML string. Landing CSS lives in `app_head.html` under `/* ============ SAAS: landing, plans, gates, toast`.
- Meta tags, OG image, theme colors, icons: `assemble_pwa.py` (the `head` template string). `og:image` currently points at `/icons/icon-512.png`; a real OG image should replace it (see below).
- Manifest and icons: `assemble_pwa.py` writes the manifest; icon files are read from `dist/icons/` and precached by the generated service worker.
- App icon art: `icon.html` (the wing on a Midnight radial). Regenerate with Playwright at 512 px, and with `?pad=0.1` for the maskable variants; downscale to 192 and 180 with Pillow.

## Putting generated assets into the site

Hard constraints, all enforced by the platform or the product:

1. **No external hosts at runtime.** Every asset is served from the site itself. No Google Fonts, no image CDNs, no `unpkg`. Put files under `site/dist/` and reference them by absolute path (`/img/hero.webp`).
2. **Offline PWA.** Anything the landing page needs goes into the service worker's precache list. In `assemble_pwa.py` the `core` list is built from `dist/icons/` and `dist/fonts/`; add a `dist/img/` scan the same way if you add images. Keep the precache under about 1.5 MB total so first install stays quick on a phone.
3. **Size budget.** Hero image at most 200 KB (WebP, quality 78 to 82, 1600 px on the long side, plus a 800 px variant for phones via `srcset`). OG image at most 300 KB (PNG or JPEG, 1200 by 630). Icons are PNG. Do not embed base64 images in `app.js`.
4. **Theme aware.** The landing renders in light and dark. A hero photo that is inherently dark works on both because the hero card is `--card` with a border; test both by toggling `data-theme` on `<html>`.
5. **Cache headers.** Add a `/img/*` block to the `_headers` template in `assemble_pwa.py` with `Cache-Control: public, max-age=31536000, immutable`, and use content-hashed filenames (`hero.3f9a1c.webp`) so a replaced image is not stuck behind the old cache.
6. **Accessibility.** `alt` text on the hero image, decorative images get `alt=""`. Contrast on text over images must meet 4.5:1; use a Midnight overlay (`linear-gradient(90deg, rgba(7,11,20,.92), rgba(7,11,20,.35))`) rather than lightening the type.
7. **No new dependencies.** The client is one IIFE in `app.js` with no framework and no build step other than `assemble_pwa.py`. Keep it that way.

Recommended wiring for a hero image: keep the phone mock (it is the product), and place the photo as the hero section background at reduced opacity behind the grid, fading to `--bg` at the bottom, so copy stays on flat Midnight. Add the `<img>` (or a `background-image` on `.hero::before`) and the gradient in `app_head.html`; do not restructure `renderWelcome()`.

For the OG image: write `dist/img/og.png` (1200 by 630), update the `og:image` line in `assemble_pwa.py` to `https://www.jetdesk.ai/img/og.png`, add `og:image:width`, `og:image:height` and change `twitter:card` to `summary_large_image`.

For new icon variants: replace the files in `dist/icons/` under the same names so the manifest and precache keep working. Apple touch icon is 180 by 180 with no transparency (iOS fills alpha with black).

## Verification checklist

Run before handing anything back:

```bash
cd site && python3 assemble_pwa.py
grep -c "og:image" dist/index.html                 # expect 1 or more
ls -la dist/img dist/icons                          # sizes within budget
node -e "JSON.parse(require('fs').readFileSync('dist/manifest.webmanifest','utf8'))"
```

Then load `http://localhost:8794/` in a 390 px wide viewport and a 1440 px viewport, light and dark, and compare against `screenshots/landing-mobile-dark.png` and `screenshots/landing-desktop-dark.png`. Nothing on the landing may scroll horizontally. The header subline `TRIP COST · FUEL · RUNWAYS` must stay on one line at 320 px.

## Things not to do

- Do not add analytics, fonts, scripts or images from third-party hosts.
- Do not scrape AirNav, ForeFlight, FltPlan or any FBO price site for imagery or data, and do not use their screenshots.
- Do not use airline, military or fighter imagery (see BRAND.md section 6).
- Do not put real customer names, tail numbers or dollar results into copy. All money on the site is the calculator's own sample (KHPN vs KBDR, 150 gal, $2.30 gap, +$191 net).
- Do not commit anything to `wrangler.toml` other than replacing placeholders in a private checkout. Do not create `.dev.vars` inside this kit.
- Do not deploy. The owner deploys from his own machine with `npx wrangler@4 pages deploy dist --project-name meridian-flight-desk`.
- Do not use em dashes anywhere in copy, code comments or docs. Use a comma, a colon, a period or parentheses instead.
